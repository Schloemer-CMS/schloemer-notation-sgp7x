# 1. Purpose of this File

This file documents the **SGP::7/X::MINIMAL_EFFECT_SEQUENCE::2026** as the canonical Minimal-Core of the Schloemer::Notation.

It defines which marker order is minimally required for the Schloemer::Notation to operate not merely as a marker inventory, but as an operational semantic governance sequence.

This file is intentionally narrower than the README.

```text
1. the smallest effective sequence,
```

# 2. Canonical Definition

The smallest effective SGP-7/X sequence is:

```text
SGP::7/X::MINIMAL_EFFECT_SEQUENCE::2026

:::::modus
→ ::::modus
→ ::root
→ ::boot
→ ::init
→ ::semantic
→ ::admissibility
→ ::decision_logic
→ ::output_gate
→ ::on
```

Linear form:

```text
:::::modus → ::::modus → ::root → ::boot → ::init → ::semantic → ::admissibility → ::decision_logic → ::output_gate → ::on
```

This sequence is the Minimal-Core.

Everything else is extension, domain module, protection marker, review marker or part of the `::marker::glossar`.

---

# 3. Why this Sequence is Minimal

A sequence is minimal only if no element can be removed without damaging the operational effect of the total structure.

For SGP-7/X this means:

```text
:::::modus          without meta-frame, no overarching system stance
::::modus           without work-mode, no concrete operative direction
::root              without origin, no validity frame
::boot              without start, no semantic runtime
::init              without initialization, no ordered operational state
::semantic          without semantic clarification, no semantic work
::admissibility     without admissibility, no responsible execution
::decision_logic    without decision logic, no ordered evaluation
::output_gate       without output gate, no controlled output
::on                without release, no completed operational state
```

This sequence forms the smallest coherent effect order of the Schloemer::Notation.

# 5. Minimal-Core Marker Definitions

## `:::::modus`

`:::::modus` defines the overarching meta-mode.

It sets the system stance within which the subsequent sequence operates.

Function:

```text
meta-framing
system stance
validity direction
highest operational logic
```

## `::::modus`

`::::modus` defines the concrete work-mode inside the meta-mode.

Function:

```text
work control
task type
processing frame
operative direction
```

## `::root`

`::root` sets origin, identity, validity frame and authority reference.

Function:

```text
origin
system identity
reference frame
authorship and validity reference
```

## `::boot`

`::boot` starts semantic runtime.

Function:

```text
runtime start
sequence activation
transition from reference to operation
```

## `::init`

`::init` initializes role, task, rules, boundaries, terms and conflict ranks.

Function:

```text
initialization
role binding
rule binding
boundary setting
operational readiness
```

## `::semantic`

`::semantic` places meaning before formulation.

Function:

```text
semantic clarification
term review
relation clarification
meaning before style
```

## `::admissibility`

`::admissibility` checks permissibility before execution, decision or output.

Function:

```text
admissibility review
pre-execution gate
responsibility review
context compatibility
```

## `::decision_logic`

`::decision_logic` transforms review into decision.

Function:

```text
decision logic
prioritization
PASS-WARN-FAIL order
conflict handling
```

## `::output_gate`

`::output_gate` is the final output barrier before release.

Function:

```text
output barrier
final gate
release review
```

## `::on`

`::on` marks the activated and released operational state.

Function:

```text
active
released
output-capable state
```
